# Payout Maximization Plan

Status: **strategy only**. This does not authorize spending, signing, posting, publishing, or submission.

## Prize Reality

The listing has two categories with the same visible prize structure:

- General Payment Volume on SAP: 1st 700 USDC, 2nd 500 USDC.
- Ace Data Cloud Usage: 1st 700 USDC, 2nd 500 USDC.

The listing also says each participant can win in only one category. So the goal is not to split effort evenly across both. The goal is to create the strongest possible submission for the category where we can most credibly rank high.

## Highest Expected Value Path

**Primary:** Ace Data Cloud Usage.

Why:

- Three distinct Ace services are already proven: OpenAI, Gemini, SERP.
- One Ace x402 payment artifact is already captured and bundled.
- Public export is red-flag-free.
- General SAP still needs Sentinel proof and escrow volume, which are heavier and less proven.

## Best Use Of "Both"

Use Synapse Sentinel / General SAP proof as a **credibility enhancer**, not as a full equal pivot.

Good:

- one legitimate Sentinel call if official path is obvious,
- one before/after Synapse Explorer snapshot after SAP registration,
- one clear explanation of SAP discovery and Synapse/SAP role.

Bad:

- chasing artificial payment volume,
- building a second full category submission that delays the stronger Ace package,
- adding unverified claims that make the whole package harder to judge.

## What Would Make Us Competitive

1. SAP mainnet registration proof.
2. One clean autonomous live run:
   - trigger,
   - SAP/tool discovery or selection,
   - Ace service execution,
   - x402 payment/facilitator evidence,
   - deliverable,
   - post-run proof bundle.
3. Public repo that is easy for judges to audit.
4. X walkthrough that is short, clear, and shows the flow.
5. Conservative claims: no reward claims, no fake volume, no private runtime.

## Work Order

1. Finish SAP mainnet identity proof.
2. Capture a single clean end-to-end Ace run.
3. Publish scoped repo after approval.
4. Post X walkthrough after approval.
5. Submit Superteam after approval.
6. Add Sentinel proof only if the official path is quick and low-risk.

## Stop Conditions

Stop or pause if:

- SAP registration requires unclear wallet risk or cost,
- Sentinel path is unclear,
- more live volume would look circular/artificial,
- public copy cannot explain the proof cleanly,
- sponsor/platform says our route is wrong.
